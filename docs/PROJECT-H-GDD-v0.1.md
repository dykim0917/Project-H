# Project H (가제) — 게임 디자인 문서

**버전:** 0.1 · 기획 초안  
**작성일:** 2026-09-08  
**기준 시제품:** Mk.III — 변형 러쉬, 배속 제거 버전  
**문서 목적:** 파칭코 시제품을 방치형 게임으로 확장하기 위한 제품 방향, 시스템 관계, 개발 범위와 미결정 사항을 정리한다.

> 이 문서는 대화에서 합의한 방향과 시제품의 현재 구현을 구분한다. 수치가 기재되어 있어도 ‘제안’과 ‘미정’은 출시 사양이 아니다. 실제 파칭코 기종을 복원하거나 실기의 출옥률을 인증하는 문서가 아니다.

## 1. 상태 표기

| 표기 | 의미 |
|---|---|
| **합의** | 사용자가 명시적으로 선택하거나 긍정한 제품 방향 |
| **현황** | 현재 코드 또는 확인된 시험 결과 |
| **제안** | 다음 개발을 진행하기 위한 초안. 승인된 사양으로 취급하지 않음 |
| **미정** | 추가 결정 또는 검증 없이는 확정할 수 없는 항목 |

기획 변경 시 날짜, 변경 이유, 영향을 받는 시스템과 기계 사양 버전을 함께 기록한다. 시제품 수치 변경이 기존 경쟁 기록의 의미를 바꾸는 경우 기록 정책도 함께 결정한다.

## 2. 게임 개요

### 한 문장 소개

**내 공간에서 캐릭터가 가상의 파칭코를 즐기는 모습을 지켜보고, 당첨과 러쉬를 경험하면서 방과 기계를 수집·꾸미는 모바일 방치형 게임.**

| 항목 | 내용 | 상태 |
|---|---|---|
| 장르 | 파칭코 관찰·수집·공간 꾸미기를 결합한 방치형 게임 | 합의 |
| 플랫폼 | 모바일. 현재 시제품은 로컬 브라우저 | 합의 / 현황 |
| 기본 화면 | 자기 공간, 캐릭터, 가동 중인 파칭코 한 대 | 합의 |
| 기계 화면 | 실제 파칭코를 경험하는 느낌의 구슬·핀·입상·추첨·러쉬 | 합의 |
| 차별점 | 러쉬 진입 때 기계가 변형되고 연짱 중 변형이 유지됨 | 합의 |
| 보상 사용 | 공간 장식, 새로운 기계 등 수집과 꾸미기 | 합의 |

| 초기 과금 | 과금 없이 시작 | 합의 |

| 출시 대상 | 파칭코 방향 유지. 높은 연령등급 가능성을 전제로 시장 검토 | 합의 / 제안 |

### 대상 이용자 가설

파칭코의 구슬 움직임, 연출, 지급음에 흥미가 있는 이용자와 조용히 관찰하며 수집하는 게임을 선호하는 이용자를 우선 고려한다. 파칭코 경험이 없는 사람도 ‘들어감 → 회전 → 당첨 → 기계가 열림’을 이해할 수 있어야 한다. 대상 연령, 국가, 규모는 조사·등급 검토 후 확정한다.

## 3. 핵심 경험과 디자인 원칙

1. **구슬의 결과가 납득되어야 한다.** 보이는 입구·핀·가이드와 입상 판정이 일치해야 한다. 이미 들어간 것처럼 보이는 구슬을 숨은 확률로 거절하지 않는다.
2. **평소와 당첨의 차이를 만든다.** 항상 번쩍이기보다, 평소의 기계음 위로 당첨과 지급이 분명하게 드러나야 한다.
3. **러쉬를 외형으로 보여준다.** 장치가 열린 상태가 특별한 플레이 상태의 표시다. 연짱마다 전체 변형을 반복하지 않는다.
4. **직접 보아도, 멀리서 보아도 재미가 있어야 한다.** 기계 확대 화면과 방 관찰 화면이 서로 다른 역할을 한다.
5. **꾸미기가 관찰 장면을 바꾼다.** 장식은 별도 목록에만 쌓이지 않고 방 화면에서 지속적으로 보인다.
6. **기계마다 개성이 있다.** 외장만 다른 복제 기계보다, 리치·변형·러쉬 놀이·지급음의 차이를 수집 동기로 삼는다.
7. **기록과 시각 효과를 분리한다.** 표시 입자 수, 화면 주사율, 소리 재생 수가 실제 지급량을 결정하지 않는다.

실제 기종의 영상·캐릭터·음원은 참고 대상으로만 취급한다. 가상 기기의 이름, 그래픽, 연출과 음향은 자체 제작하거나 이용 권한이 확보된 자산을 사용한다.

## 4. 플레이 순환

### 순간 순환 — 기계

발사 → 구슬의 핀·가이드 통과 → 시동구 입상 → 보류 → 숫자 회전 → 리치 또는 낙첨 → 당첨 → 지급 → 변형 러쉬 → 연장 또는 종료 → 일반 상태.

### 접속 중 순환 — 관찰과 선택

방 확인 → 기계 선택·발사 세기 설정 → 캐릭터의 플레이 관찰 → 당첨·기록 확인 → 획득 보상으로 꾸미기 → 달라진 방 관찰.

### 장기 순환 — 수집과 경쟁

플레이 기록 축적 → 공간과 기계 해금 → 다른 기계의 특별한 연출 경험 → 개인 기록 갱신·시즌 경쟁 → 새 기계와 장식 수집.

**제안:** 당첨 보너스 외에 기본적인 꾸미기 진행을 제공한다. 불운이 길어져도 방이 조금씩 바뀌되, 당첨이 목표 달성을 분명하게 앞당기도록 한다. 기본 보상의 산식은 미정이다.

## 5. 화면과 사용자 흐름

### 5.1 방 관찰 화면 — 제안

- 캐릭터 한 명과 현재 가동 기계 한 대를 중심으로 구성한다.
- 보유 기계 전시 여부와 방 확장 방식은 후속 결정한다.
- 기계의 조명이 방에 반영되고, 당첨 때 캐릭터가 반응한다.
- 기계를 누르면 판면을 확대한다. 러쉬 진입만으로 강제 확대하지 않는다.
- 필요한 재화, 기계 상태, 꾸미기·수집 접근만 간결하게 표시한다.

### 5.2 기계 화면 — 합의 및 현황

구슬 경로, 숫자 계기, 기계장치, 최소 HUD와 좌우 화살표 핸들로 구성한다. 장문의 설명과 개발용 통계를 기본 화면에 노출하지 않는다. 배속은 없다.

현재 조작은 발사 시작/정지, 발사 세기, 소리, 초기화, 러쉬 체험이다. 초기화와 러쉬 체험은 개발용 기능으로, 출시 버전의 경쟁 플레이 UI와 구분한다.

### 5.3 꾸미기 화면 — 제안

물건 선택 → 방에 배치 미리보기 → 구입·배치 → 방 화면에서 확인. 배치 취소 시 재화가 잘못 차감되지 않아야 한다. 장식은 초기에는 외형과 캐릭터 동작을 바꾸고, 당첨 확률을 높이는 필수 장비로 만들지 않는다.

### 5.4 복귀 결산 — 제안

부재 시간, 유효 가동 시간, 당첨 수, 최고 연짱, 획득 보상, 갱신 기록을 짧게 보여준다. 최고 순간 다시보기는 선택 기능으로 검토한다. 보상은 결산 확인·다시보기 시청 여부와 무관하게 한 번만 반영한다.

## 6. 캐릭터와 공간

**합의:** 캐릭터가 자신의 공간에서 파칭코를 하는 모습을 관찰한다.

**제안:** 초기 동작은 대기, 평상시 플레이, 자세 변경, 리치 집중, 당첨 반응으로 제한한다. 상태를 전달하는 동작부터 만들고 복잡한 생활 시뮬레이션은 후순위로 둔다.

초기 장식 후보는 의자, 조명, 벽 장식, 바닥·벽 테마, 작은 테이블이다. 방의 조명과 기계 조명이 충돌해 판면이 보이지 않는 상황을 피한다. 캐릭터의 취향·친밀도·성장 능력치는 아직 도입하지 않는다.

## 7. 파칭코 공통 규칙

### 7.1 발사와 입상

- 핸들 양옆 화살표로 힘을 조절한다. 손을 떼면 설정을 유지한다.
- 구슬끼리, 구슬과 핀·벽의 충돌을 표현한다.
- 발사 레일과 상단의 둥근 경로를 통해 세기에 따른 좌·우 이동을 제공한다.
- 구슬이 시동구 유효 영역을 실제로 통과할 때 보류를 추가한다.
- 보류 상한 초과 입상은 추가 추첨을 저장하지 않는다. 상구 처리 규칙은 공통 사양으로 명시한다.
- 보류가 있는 상태에서 가능한 다음 회전을 순차 처리한다.

### 7.2 일반 추첨과 리치

현재 가상 기기는 회전 시작 시 당첨 여부를 정하고 숫자와 룰렛으로 결과를 표현한다. 숫자 일치는 당첨 결과와 일관되어야 한다. 물리 구슬의 입상과 숫자 추첨을 혼동하지 않는다.

### 7.3 헤소 가독성 — 알려진 개선 과제

현재 Mk.III는 두 개의 시동구와 넓은 유도 가이드를 사용한다. 사용자는 시선 분산 및 가이드에 들어온 구슬이 최종 입구에서 빠지는 상황을 지적했다.

**후속 설계 방향:** 중앙에 관심을 모으고, 입상률 조절을 최종 구멍보다 앞쪽의 분기 구간에서 수행한다. 최종 가이드를 제대로 탄 구슬은 대부분 입상하게 한다. 모든 구슬을 입상시키거나 숨은 확률로 걸러내는 방식은 사용하지 않는다. 시동구 수와 최종 판면 변경은 다음 기계 설계에서 결정한다.

## 8. 변형 러쉬

**합의된 흐름:** 최초 당첨 → 지급 → 기계 변형 → 러쉬 → 연짱 중 변형 유지 → 실패 시 원래 기계로 복귀.

현재 Mk.III에서는 중앙 숫자 룰렛이 접히고 양쪽 프레임이 벌어져 내부 회전 접시를 드러낸다. 세 구슬 중 하나라도 연장 영역에 도착하면 추가 당첨 한 번으로 처리한다. 한 도전에서 여러 구슬이 성공해도 여러 번 지급하지 않는다.

| 상태 | 진입 | 행동 | 종료 조건 |
|---|---|---|---|
| 일반 | 초기·러쉬 종료 | 시동 입상과 숫자 추첨 | 당첨 |
| 당첨 해제 연출 | 최초 당첨 | 짧은 간격과 잠금 해제음 | 지급 시작 |
| 최초 지급 | 첫 당첨 | 정해진 지급량 처리 | 지급 완료 |
| 변형 | 최초 지급 완료 | 장치를 열고 내부 구조 노출 | 개방 완료 |
| 러쉬 도전 | 변형 완료·연짱 지급 완료 | 세 구슬 결과 표시 | 성공 또는 전부 실패 |
| 연짱 지급 | 러쉬 성공 | 열린 상태에서 추가 지급 | 다음 도전 |
| 복귀 | 러쉬 실패 | 장치 닫기 | 일반 상태 |

현재 내부 러쉬 구슬은 최종 각도 추첨을 경로·감속으로 표현하는 간이 모델이다. 외부 판면의 자유 구슬 물리와 동일한 모델이 아니다. 후속 기계에서 실제 물리 기반 장치를 쓸지, 결과를 연출하는 장치를 쓸지 기계별로 명시한다.

## 9. 지급 라운드와 음향

### 9.1 방향

**합의:** 구슬 지급의 소리와 움직임을 핵심 쾌감으로 삼는다. 현재보다 천천히, 라운드별로 끊어서 지급되는 느낌을 지향한다.

**제안:** 공통 지급 시스템을 만들고 기계별로 총 지급량, 라운드 수, 라운드당 지급량, 지급 속도와 휴지 시간을 설정한다. 모든 기계의 수치를 같게 고정하는 것은 확정되지 않았다.

예시 초안은 총 300개를 60개씩 5라운드로 나누고, 각 라운드 2초 지급 후 0.5초 쉬는 방식이다. 이는 미구현·미승인 예시이며 실기 라운드 규격을 뜻하지 않는다.

러쉬 도전 횟수, 연짱 수, 한 당첨의 지급 라운드는 서로 다른 용어로 사용한다. 지급 라운드가 다섯 번이라고 5연짱으로 기록하지 않는다.

### 9.2 지급의 정확성

- 실제 보상은 지급 이벤트로 집계하고 애니메이션 입자 수와 분리한다.
- 라운드 ID와 지급 순서를 기록해 복귀·재접속 시 중복 지급을 막는다.
- 지급 도중 앱을 닫았을 때 남은 지급·다음 러쉬를 어떻게 이어갈지 공통 상태 규칙을 적용한다.
- 지급 시간도 기계의 전체 가동 시간을 구성한다. 시간이 다른 기계를 경쟁에서 비교할 때 반영한다.

### 9.3 음향 구성

평상시 발사음·핀 충돌음, 리치의 기계식 걸림음, 당첨 잠금 해제음, 지속적인 구슬 흐름, 불규칙한 금속 충돌음, 받침 울림, 변형 모터음, 마지막 몇 알의 잔향을 구분한다.

현재는 합성음이다. 후속 품질 개선 시 직접 녹음 또는 사용 권한이 있는 구슬·받침 녹음을 검토한다. 소리와 보이는 충돌을 가능한 범위에서 연결하고, 음소거·앱 중단 시 지속음이 남지 않게 한다. 마스터 음량과 기계음·음악 분리는 설정 화면 후보로 둔다.

## 10. 재화와 경제

**합의 방향:** 기록용 구슬과 꾸미기 진행 재화를 분리하고 획득 보상을 공간·기계 수집에 사용한다.

| 항목 | 역할 | 미결정 사항 |
|---|---|---|
| 구슬·기계 기록 | 발사, 지급, 차옥, 당첨과 연짱의 원자료 | 실제 소모 잔고를 둘지, 고갈 시 어떻게 할지 |
| 꾸미기 코인(가칭) | 가구·외형·기계 해금에 소비 | 기본 획득량, 당첨 보너스, 가격, 교환 방식 |
| 경쟁 점수 | 기록에서 산출한 비교 지표. 소비 재화가 아님 | 누적 지급·차옥·별도 점수 중 선택 |

현재 시제품은 발사 비용을 잔고에서 차감하지 않고 누적 지급량만 표시한다. 따라서 현재 ‘획득 구슬’을 순이익으로 해석하면 안 된다. 실기 손익이나 천 엔당 회전율과 직접 비교하지 않는다.

**제안:** 꾸미기를 구매해도 과거 경쟁 점수는 감소하지 않게 한다. 불운한 기간의 최소 진행을 제공하되 클릭·재접속 반복으로 기본 보상을 중복 획득할 수 없게 한다. 코인 전환 시점과 대상 지급량을 명확히 정의한다.

기계 구입을 단순한 상위 수익 장비 구매로 만들지 않는 방향을 우선 검토한다. 외형 장식이 경쟁 성능을 바꾸지 않도록 하는 것도 제안이며 최종 경제 사양은 별도 확정한다.

## 11. 방치·오프라인 진행

### 현재와 목표의 구분

**현황:** 브라우저 탭이 숨겨지면 구슬·추첨·러쉬가 멈춘다. 서버, 계정 저장과 오프라인 보상은 없다.

**제안:** 앱을 꺼도 정해진 상한까지 가동 시간을 인정한다. 이는 ‘화면 접속시간만 경쟁’이라는 최초 구상을 변경하는 제안이므로 별도 결정이 필요하다.

결정할 항목은 오프라인 허용 여부·시간 상한, 발사 세기 유지 방식, 부재 중 기계 변경 제한, 중간 러쉬의 이어하기, 보상 집계 시점이다.

### 일관성 요구사항

- 같은 규칙·버전·유효 가동 시간에서 앱 표시 여부로 기대 성능이 달라지지 않아야 한다.
- 저성능 기기의 프레임 손실이 곧 점수 손실이 되어서는 안 된다.
- 휴대폰 시계 변경, 재설치, 여러 기기 중복 접속으로 가동 시간을 늘릴 수 없어야 한다.
- 보상과 확정 결과는 다시보기를 재생하거나 건너뛰어도 같아야 한다.
- 지급 중 종료와 재접속을 상태 전이로 다루고 새 추첨으로 덮어쓰지 않는다.

**미정:** 오프라인에도 같은 물리 계산을 실행할지, 검증된 입상 모델로 경량화할지. 단순 시간당 평균 보상만 적용하면 운의 편차와 연짱 기록이 사라진다. 경량화할 경우 온라인과의 입상률·당첨 간격·분산·러쉬 지속시간 차이를 검증해야 한다. 차이가 해결되기 전에는 두 방식의 경쟁 기록을 무조건 동일 취급하지 않는다.

## 12. 경쟁과 랭킹

**합의:** 과금 우위 없이 운과 시간으로 경쟁하며, 순위가 갱신되는 모습을 제공한다. 배속은 제외한다.

**미정:** 실제 접속시간과 오프라인을 포함한 유효 가동시간 중 무엇을 경쟁에 반영할지, 시즌 길이와 점수 산식.

### 초안 구조

- **제안 A — 기계별 주간 누적 경쟁:** 유효 기간의 구슬 기록을 누적한다. 최초의 시간 경쟁 의도를 유지하지만 오래 가동한 이용자가 유리하다.
- **제안 B — 동일 조건 도전:** 같은 기계와 정해진 발사 수·시간으로 비교한다. 시간 격차는 줄지만 최초의 누적 시간 경쟁과는 다른 별도 모드다.
- **개인 기록 제안:** 최고 연짱, 단일 러쉬 최고 지급, 최초 달성일, 누적 당첨. 초기에는 자기 기록 갱신만으로도 목표를 제공한다.

두 경쟁 방식을 모두 초기 범위에 넣지 않는다. 핵심 이용자 경험을 확인한 뒤 한 가지를 선택한다. 현재 시제품에는 랭킹이 구현되지 않았다.

### 공통 기록 원칙 — 제안

기계 ID와 사양 버전, 경쟁 기간, 유효 가동 시간, 발사 수, 시동 입상 수, 일반 회전 수, 최초 당첨 수, 러쉬 추가 당첨 수, 실제 지급량, 체험 여부를 보존한다. 총 대당첨 표시와 최초 당첨·추가 당첨 원자료는 분리한다.

서로 다른 기계를 같은 기대값이라는 이유만으로 단순 합산하지 않는다. 변동성·지급 소요시간·상한 차이까지 평가해야 한다. 초기에는 같은 기계·같은 사양 버전의 비교가 우선이다. 밸런스 변경은 시즌 경계 적용 또는 기록 분리 정책이 필요하다.

실시간 갱신 주기는 서버 비용과 표시 반응을 확인해 정한다. 판면의 모든 프레임을 순위 서버에 보내는 구조를 전제로 하지 않는다. 서버 검증·확정 기록과 로컬 체험 데이터를 분리한다.

## 13. 기계 수집과 콘텐츠 제작

**합의:** 새 가상 기계를 계속 추가해 흥미를 유지한다. 실제 파칭코의 큰 틀을 공유하되 기계마다 다른 경험을 만든다.

공통 엔진은 발사·입상·보류·추첨·지급·저장·기록을 담당한다. 기계별 데이터와 연출은 판면, 확률, 상태별 시간, 리치, 변형, 러쉬 장치, 음향을 담당한다. 콘텐츠와 공통 규칙의 경계를 먼저 검증한다.

### 기계 사양서 템플릿

| 영역 | 필수 기재 내용 |
|---|---|
| 식별 | 기계 ID, 이름, 사양 버전, 테마 |
| 판면 | 핀·레일·가이드·시동구, 발사 세기 범위, 유효 입상 모델 |
| 일반 | 당첨 확률, 보류 상한, 회전·리치 시간, 리치 분기 |
| 러쉬 | 진입 조건, 연장 방식·확률, 종료 조건, 연짱 집계 |
| 지급 | 총량, 지급 라운드, 속도·휴지 시간, 상구 |
| 표현 | 평상시·변형 외형, 상태별 동작, 음향과 필요한 자산 |
| 검증 | 끼임·입상률, 지급 정확성, 장기 표본 분포, 온라인/오프라인 일치 |
| 운영 | 해금 조건, 경쟁 분류, 변경 시 기존 기록 처리 |

첫 콘텐츠 방향은 작은 숫자창과 기계식 장치를 우선한다. 대형 화면·영상 중심 기기는 확장 가능성으로 남기되 초기 제작 전제로 삼지 않는다. 영상은 필요한 특수 연출에 제한적으로 사용할 수 있다.

출시 주기는 미정이다. 두세 기계의 실제 제작 시간·자산 수·검증 비용을 측정한 뒤 운영 일정을 잡는다.

## 15. 초기 과금과 출시 조건

초기 버전은 과금 없이 개발한다. 향후 과금은 사용자 피드백과 운영 비용을 바탕으로 별도 결정한다. 과거 논의한 ‘답답함 해소 과금’은 채택된 사양이 아니다.

**제안:** 과금 검토 시 먼저 방 테마·캐릭터 의상·기계 외장 등 외형 상품을 검토한다. 확률·속도·가동 시간·성능을 판매할 경우 기존 경쟁 원칙과 충돌하므로 같은 시스템에 무심코 추가하지 않는다.

파칭코와 모의 도박 요소를 유지한다는 방향은 확인되었다. 이것이 출시 등급이나 유통 승인을 확보했다는 뜻은 아니다. 환전·현금성 경품·유저 간 현금 거래는 현재 범위에 없다.

2026-09-08 확인한 Apple 공식 안내는 빈번한 모의 도박을 현행 글로벌 18+ 및 한국 지역 19+ 항목에 포함하고, 한국 배포에 해당 콘텐츠의 등급분류번호(RCN)를 요구한다. 실제 적용은 플랫폼·지역·최종 콘텐츠별 확인이 필요하다. Android를 Apple 기준으로 자동 판정하지 않는다. 출시 국가, 배포 플랫폼, 필요한 등급 절차는 출시 준비 전에 확인한다.

참고: [Apple 연령등급 정의](https://developer.apple.com/help/app-store-connect/reference/app-information/age-ratings-values-and-definitions/), [Google Play 실제 금전 도박 정책](https://support.google.com/googleplay/android-developer/answer/9877032?hl=en). 후자는 현금·현실 가치 보상 경계를 검토하기 위한 자료이며 현재 게임의 등급 확정 근거는 아니다.

## 16. 초기 개발 범위 — 제안

### 단계 1: 방치형 경험 연결

방 한 개, 캐릭터 한 명, Mk.III 한 대, 소수의 장식, 방↔기계 전환, 로컬 진행 저장, 기본 꾸미기 구매를 연결한다. 지급 라운드 개선을 함께 검토한다. 온라인 랭킹과 대규모 콘텐츠를 앞서 만들지 않는다.

**확인할 결과:** 기계를 확대하지 않은 방 화면도 관찰할 이유가 있는지, 당첨이 없어도 진행을 느끼는지, 새 장식을 배치했을 때 장면이 달라지는지.

### 단계 2: 부재와 복귀

오프라인 규칙을 확정하고 시간·보상·중단 상태를 연결한다. 복귀 결산과 개인 기록을 제공한다. 다시보기는 핵심 결산 이후로 둔다.

**확인할 결과:** 여러 번 재접속해도 중복 지급되지 않는지, 지급·러쉬 중 종료가 일관되게 이어지는지, 켜둔 상태와의 성능 차이가 허용 범위인지.

### 단계 3: 기계 확장과 경쟁

두 번째 기계로 데이터·연출 교체 구조를 검증한다. 기록 확정 구조와 기계별 비교를 연결한다. 시즌 방식과 점수 산식을 결정한 뒤 외부 경쟁 시험을 진행한다.

초기 제외 항목은 다수 기계 동시 수익, 길드·거래, 복잡한 캐릭터 성장, 대형 영상 콘텐츠, 유료 확률·배속, 현금성 보상이다. 일정·예산·팀 규모는 미정이다.

## 17. 검증 계획

| 질문 | 확인 방법 |
|---|---|
| 입상이 납득되는가? | 가이드 진입 후 결과 관찰, 실제 기기에서 구슬 경로 확인 |
| 방만 보아도 상태가 전달되는가? | 확대 없이 리치·당첨·러쉬를 구분하는지 관찰 |
| 지급이 즐거운가? | 휴대폰 스피커·이어폰에서 소리와 입자 타이밍 비교 |
| 당첨 없는 시간도 견딜 만한가? | 불운한 세션을 포함한 플레이 관찰, 꾸미기 진행 확인 |
| 다시 접속할 이유가 있는가? | 결산 이해, 다음 구매 목표, 자발적 재방문 관찰 |
| 기계를 바꿀 이유가 있는가? | 수익 수치 외에 선호하는 소리·연출·형태가 생기는지 확인 |
| 기록이 공정한가? | 재접속·프레임 차이·시계 변경·버전 차이·중복 처리 시험 |

측정 후보는 방/기계 화면 체류 비율, 최초 구매까지 시간, 시동 입상률, 분당 유효 회전, 보류 포화·공백 시간, 당첨 간격 분포, 러쉬 길이 분포, 실제 지급량, 재방문과 기계 교체 빈도다. 목표 수치는 아직 정하지 않는다. 평균만 확인하지 않고 긴 미당첨 구간과 극단적인 연짱도 확인한다.

| 발사 | 약 0.6초 간격, 기본 세기 36%, 배속 없음 |
| 시동구 | 두 곳, 각 폭 14(판면 좌표 단위) |
| 최초 당첨 지급 | 300개, 약 5초 지급 후 짧은 대기 |
| 러쉬 진입 | 최초 당첨 후 진입 |
| 러쉬 연장 | 세 알 독립, 각 38%; 합성 확률 76.1672% |

| 지급 입자 | 실제 지급 5개당 시각 입자 1개, 받침 표시 최대 36개 |
| 백그라운드 | 일시정지 |
| 저장·방·재화 상점·랭킹 | 미구현 |

Mk.2.5 판면 조정 시험에서 기본 세기 36%의 입상은 900발당 90회였다. 이는 시험 표본이며 기계의 보편적인 입상률이나 실기 보더가 아니다. Mk.III는 해당 판면을 재사용한다.

Mk.III 로직·조작·음향 제어 검사 9개가 통과했다. 브라우저 정책 확인 도구 장애로 도구를 통한 실제 화면·스피커 직접 검증은 미완료다. 사용자는 직접 플레이 후 변형 러쉬를 긍정적으로 평가했으나, 이는 정량적인 사용자 조사 결과가 아니다.
