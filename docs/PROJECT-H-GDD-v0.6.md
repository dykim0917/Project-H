# Project H (가제) — 게임 디자인 문서

**버전:** 0.6 · 기획 초안  
**작성일:** 2026-09-09  
**기준본:** v0.5 기반 · 이전 버전 보존 · 기본 방과 첫 당첨·구매 튜토리얼 합의 반영  
**기준 시제품:** Mk.III — 변형 러쉬, 배속 제거 버전  
**문서 목적:** 파칭코 시제품을 방치형 게임으로 확장하기 위한 제품 방향, 시스템 관계, 개발 범위와 미결정 사항을 정리한다.

> 이 문서는 대화에서 합의한 방향과 시제품의 현재 구현을 구분한다. 수치가 기재되어 있어도 ‘제안’과 ‘미정’은 출시 사양이 아니다. 실제 파칭코 기종을 복원하거나 실기의 출옥률을 인증하는 문서가 아니다.

## 1. 상태 표기

| 표기 | 의미 |
|---|---|
| **합의** | 사용자가 명시적으로 선택하거나 긍정한 제품 방향 |
| **현황** | 현재 코드 또는 확인된 시험 결과 |
| **제안** | 다음 개발을 진행하기 위한 초안. 승인된 사양으로 취급하지 않음 |
| **미정** | 추가 결정 또는 검증 없이는 확정할 수 없는 항목 |

기획 변경 시 날짜, 변경 이유, 영향을 받는 시스템과 기계 사양 버전을 함께 기록한다. 시제품 수치 변경이 기존 경쟁 기록의 의미를 바꾸는 경우 기록 정책도 함께 결정한다.

## 2. 게임 개요

### 한 문장 소개

**내 공간에서 캐릭터가 가상의 파칭코를 즐기는 모습을 지켜보고, 당첨과 러쉬를 경험하면서 방과 기계를 수집·꾸미는 모바일 방치형 게임.**

| 항목 | 내용 | 상태 |
|---|---|---|
| 장르 | 파칭코 관찰·수집·공간 꾸미기를 결합한 방치형 게임 | 합의 |
| 플랫폼 | 모바일. 현재 시제품은 로컬 브라우저 | 합의 / 현황 |
| 기본 화면 | 자기 공간, 캐릭터, 가동 중인 파칭코 한 대 | 합의 |
| 기계 화면 | 실제 파칭코를 경험하는 느낌의 구슬·핀·입상·추첨·러쉬 | 합의 |
| 차별점 | 러쉬 진입 때 기계가 변형되고 연짱 중 변형이 유지됨 | 합의 |
| 보상 사용 | 공간 장식, 새로운 기계 등 수집과 꾸미기 | 합의 |
| 경쟁 | 일상 플레이와 가상의 파칭코 그랑프리를 구분. 대회 기록과 순위 제공 | 합의 |
| 초기 과금 | 초기 직접 결제 없음. 부재 코인 감액·광고 복원 방향 합의, 초기 도입 여부 미정 | 합의 / 제안 |
| 배속 | 제공하지 않음 | 합의 / 현황 |
| 향후 과금 | 도입 여부·시점·상품·경쟁과의 관계 모두 미확정 | 미정 |
| 출시 대상 | 파칭코 방향 유지. 높은 연령등급 가능성을 전제로 시장 검토 | 합의 / 제안 |

### 대상 이용자 가설

파칭코의 구슬 움직임, 연출, 지급음에 흥미가 있는 이용자와 조용히 관찰하며 수집하는 게임을 선호하는 이용자를 우선 고려한다. 파칭코 경험이 없는 사람도 ‘들어감 → 회전 → 당첨 → 기계가 열림’을 이해할 수 있어야 한다. 대상 연령, 국가, 규모는 조사·등급 검토 후 확정한다.

## 3. 핵심 경험과 디자인 원칙

1. **구슬의 결과가 납득되어야 한다.** 보이는 입구·핀·가이드와 입상 판정이 일치해야 한다. 이미 들어간 것처럼 보이는 구슬을 숨은 확률로 거절하지 않는다.
2. **평소와 당첨의 차이를 만든다.** 항상 번쩍이기보다, 평소의 기계음 위로 당첨과 지급이 분명하게 드러나야 한다.
3. **러쉬를 외형으로 보여준다.** 장치가 열린 상태가 특별한 플레이 상태의 표시다. 연짱마다 전체 변형을 반복하지 않는다.
4. **직접 보아도, 멀리서 보아도 재미가 있어야 한다.** 기계 확대 화면과 방 관찰 화면이 서로 다른 역할을 한다.
5. **꾸미기가 관찰 장면을 바꾼다.** 장식은 별도 목록에만 쌓이지 않고 방 화면에서 지속적으로 보인다.
6. **기계마다 개성이 있다.** 외장만 다른 복제 기계보다, 리치·변형·러쉬 놀이·지급음의 차이를 수집 동기로 삼는다.
7. **기록과 시각 효과를 분리한다.** 표시 입자 수, 화면 주사율, 소리 재생 수가 실제 지급량을 결정하지 않는다.

실제 기종의 영상·캐릭터·음원은 참고 대상으로만 취급한다. 가상 기기의 이름, 그래픽, 연출과 음향은 자체 제작하거나 이용 권한이 확보된 자산을 사용한다.

### 3.1 접속 부담과 관찰의 재미

**합의 방향:** 짧게 확인해도 만족할 수 있고, 오래 켜두고 바라볼 이유도 있어야 한다. 콘텐츠가 반복 의무나 숙제로 느껴지지 않도록 세부 규칙을 다듬는다. 이는 설계 목표이며 현재 시제품에서 검증된 성과는 아니다.

**제안:** 오래 켜둘 동기는 구슬 움직임·소리, 리치의 긴장, 기계 변형, 캐릭터 반응과 달라진 방에서 찾는다. 단순 접속 보너스나 즉시 반응하지 않으면 잃는 보상으로 체류를 유도하는 방식은 우선안으로 삼지 않는다. 짧은 접속을 실패한 세션으로 간주하지 않는다.

다음 항목은 콘텐츠를 추가할 때의 검토 기준이다.

- 접속마다 수금·갱신·여러 메뉴 방문을 반복해야만 정상 진행되는가?
- 러쉬를 못 본 아쉬움이 보상을 잃을 불안으로 바뀌는가?
- 새 기능이 새로운 선택을 주는가, 확인해야 할 타이머만 늘리는가?
- 대회를 쉬거나 좋아하는 옛 기계를 써도 일상 수집을 이어갈 수 있는가?
- 긴 미당첨 구간에도 다음 꾸미기 목표와 눈에 보이는 변화가 남는가?

**후속 합의:** 부재 인정은 최대 24시간이다. 일상에서 온라인 관찰의 기대 수익 우위를 허용하며, 부재 코인을 감액하고 광고로 감액분을 복원해 시청을 유도한다. 광고 미시청의 기회비용을 의도적으로 두는 방향으로 기존 부담 완화 목표를 조정한다. 짧은 접속·광고 미시청으로도 진행은 가능하지만 같은 코인 수입을 보장하지 않는다. 세부 규칙은 10·11·15장에 따른다.

## 4. 플레이 순환

### 순간 순환 — 기계

발사 → 구슬의 핀·가이드 통과 → 시동구 입상 → 보류 → 숫자 회전 → 리치 또는 낙첨 → 당첨 → 지급 → 변형 러쉬 → 연장 또는 종료 → 일반 상태.

### 접속 중 순환 — 관찰과 선택

방 확인 → 기계 선택·발사 세기 설정 → 캐릭터의 플레이 관찰 → 당첨·기록 확인 → 획득 보상으로 꾸미기 → 달라진 방 관찰.

### 장기 순환 — 수집과 경쟁

플레이 기록 축적 → 공간과 기계 해금 → 다른 기계의 특별한 연출 경험 → 개인 기록 갱신·시즌 경쟁 → 새 기계와 장식 수집.

**제안·검증 가설:** 꾸미기 코인은 기계 당첨으로 획득하고, 미당첨 구간의 작은 즐거움은 펫의 랜덤 수집으로 보완한다. v0.3의 기본 코인 + 당첨 보너스안 대신 먼저 검토할 초안이다. 불운한 날에도 만족스러운지 검증한 뒤 기본 코인 지급 필요성을 판단한다. 기본 지급을 영구 배제한 합의는 아니다.

### 4.1 상황에 따라 달라지는 접속 흐름 — 제안

이용자를 고정된 유형으로 나누지 않는다. 같은 사람이 하루 중 여러 방식으로 이용할 수 있다.

| 이용 상황 | 접속 중 행동 예시 | 얻고 나가는 만족 | 설계에서 확인할 점 |
|---|---|---|---|
| 짧게 확인 | 방·기계 상태와 새 기록 확인, 원하면 소품 구매 후 종료 | 내 공간이 조금 진행됐다는 느낌 | 구매나 여러 메뉴 방문 없이도 종료 가능 |
| 곁에 켜두기 | 다른 일을 하며 가끔 관찰, 소리나 변형에 관심이 가면 확대 | 움직이는 기계의 분위기와 가끔 오는 특별한 순간 | 반복 조작·즉시 반응 요구, 피로한 음향 여부 |
| 집중해서 놀기 | 기계 관찰·교체, 방 배치, 선택적으로 그랑프리 참가 | 발견·선택·개인 목표와 기록 | 집중할 때 할 일이 있고 원할 때 중단 가능 |
| 쉬었다 복귀 | 유지된 수집품과 현재 목표 확인 후 재개 | 익숙한 공간에 돌아온 느낌 | 밀린 필수 과제·강제 안내의 부담 |

‘곁에 켜두기’는 앱을 화면에 띄워 놓고 주의를 덜 주는 상황이다. 다른 앱으로 전환하거나 앱을 종료한 상태의 진행과 구분한다. 현재 시제품은 탭이 숨겨지면 멈춘다.

**현재 기획 초안:** 4.2·4.3에 1분 확인·20분 관찰 흐름을 작성했다. 시간은 실제 평균이나 보상 기준이 아니다. 부재 정산과 펫 발견·코인 구매 흐름을 먼저 검증하고, 그랑프리는 별도로 구체화한다.

### 4.2 1분 확인하고 나가는 하루 — 제안
시간은 검토용 시나리오이며 평균 접속 시간·의무 체류·보상 기준이 아니다. 부재 중 진행 인정과 복귀 팝업은 합의다. 아래 흐름은 펫 발견 및 코인 지급이 구현된 상황을 가정한다. 매 복귀마다 당첨·발견·구매가 발생한다는 뜻은 아니다.

| 구간 | 보고 선택하는 것 | 얻는 것과 종료 가능성 |
|---|---|---|
| 0~15초 | 복귀 팝업에서 인정된 가동 시간, 당첨·최고 연짱, 코인 확인 | 부재 중 결과를 이해. 바로 닫고 나갈 수 있음 |
| 15~30초 | 광고 미도입 시 기본 결과 확인. 도입 시 감액 코인 수령 또는 광고로 감액분 복원을 선택 | 감액된 기본 지급은 보존하는 안을 우선한다. 광고를 고르면 실제 세션은 1분보다 길어질 수 있음 |
| 30~45초 | 펫이 가져온 물건이 있을 때 확인. 없으면 현재 방과 목표 확인 | 새 수집품 또는 유지된 공간을 확인. 발견 연출 건너뛰기 가능 |
| 45~60초 | 원하면 소품 구매·배치, 아니면 방을 잠깐 보고 종료 | 메뉴 방문·구매 없이 종료 가능. 광고 미시청 시 코인 감액 적용 |

팝업의 표현 순서는 코인 결산 → 펫 발견을 초안으로 둔다. 펫 보상을 같은 팝업에 통합할지 별도로 보여줄지는 D17에서 결정한다. 최초 시작 안내는 5.5에서 다룬다. 일반 복귀에서는 튜토리얼 반복·연속 팝업·다시보기로 짧은 확인을 늘리지 않는다. 새 보상이나 발견이 없는 재접속에 같은 팝업을 반복할지는 검토하되, 이미 처리한 결과를 다시 지급하지 않는다.

### 4.3 20분 곁에 켜두는 하루 — 제안
앱 화면을 켠 채 다른 활동과 병행하는 상황이다. 다른 앱 전환·화면 끄기는 부재 중 처리 규칙을 따른다.

| 구간·상황 | 행동과 표현 | 기대하는 만족 |
|---|---|---|
| 처음 1~2분 | 복귀 결과 확인, 원하면 기계·핸들 선택 | 오늘 관찰할 장면 선택 |
| 평상시 | 방에서 캐릭터·기계·펫을 관찰하며 다른 일 병행 | 소리·움직임·공간의 분위기 |
| 리치·당첨 발생 시 | 원할 때 확대. 지급 후 기계 변형과 러쉬 감상 | 긴장·해소와 기계 변화. 즉시 조작은 보상 조건이 아님 |
| 펫 발견 시 | 소품을 가져오는 모습을 확인하거나 나중에 확인 | 기계 결과 외의 작은 사건. 20분 내 발견 보장 없음 |
| 원할 때 종료 | 그대로 종료하거나 수집품 배치 | 확정된 보상 보존. 부재 가동 후 정산 경계의 미확정 연장 기회 종료. 킵은 별도 후보 |

당첨·펫 발견이 모두 없는 세션도 시험한다. 펫 랜덤 수집을 추가했다고 미당첨 구간의 만족이 자동 보장되지는 않는다. 무미건조하다면 일일 미션을 늘리기 전에 평상시 관찰 재미, 당첨·발견 간격과 코인 기본 진행 필요성을 검토한다.

## 5. 화면과 사용자 흐름

### 5.1 방 관찰 화면 — 제안

- 캐릭터 한 명과 현재 가동 기계 한 대를 중심으로 구성한다.
- 보유 기계 전시 여부와 방 확장 방식은 후속 결정한다.
- 기계의 조명이 방에 반영되고, 당첨 때 캐릭터가 반응한다.
- 기계를 누르면 판면을 확대한다. 러쉬 진입만으로 강제 확대하지 않는다.
- 필요한 재화, 기계 상태, 꾸미기·수집 접근만 간결하게 표시한다.

### 5.2 기계 화면 — 합의 및 현황

구슬 경로, 숫자 계기, 기계장치, 최소 HUD와 좌우 화살표 핸들로 구성한다. 장문의 설명과 개발용 통계를 기본 화면에 노출하지 않는다. 배속은 없다.

현재 조작은 발사 시작/정지, 발사 세기, 소리, 초기화, 러쉬 체험이다. 초기화와 러쉬 체험은 개발용 기능으로, 출시 버전의 경쟁 플레이 UI와 구분한다.

### 5.3 꾸미기 화면 — 제안

물건 선택 → 방에 배치 미리보기 → 구입·배치 → 방 화면에서 확인. 배치 취소 시 재화가 잘못 차감되지 않아야 한다. 장식은 초기에는 외형과 캐릭터 동작을 바꾸고, 당첨 확률을 높이는 필수 장비로 만들지 않는다.

### 5.4 복귀 결산
**합의:** 부재 결과를 팝업으로 확인하고 기계는 항상 통상 상태로 복귀한다. 부재 코인은 감액 지급하며 광고 시청 시 감액분을 복원한다. 기존의 무조건 2배 보너스안과 접속 여부 무관 별도 코인 보너스안은 채택하지 않는다.

**제안:** 실제 부재 시간·인정 시간(최대 24시간), 당첨·최고 연짱, 감액 전 기준 코인·기본 수령량·광고 복원분을 구분해 표시한다. 버튼은 `기본 수령` / `광고 보고 전액 수령`을 후보로 둔다. 전액은 부재 정산 결과에 온라인과 같은 코인 전환율을 적용한 금액이며, 온라인으로 같은 시간을 플레이했을 가상 결과를 보장하지 않는다.

정산 끝에 미확정 연장 기회는 종료한다. 이미 확정된 당첨·구슬 지급은 보존하며, 이 원칙과 코인 전환 시 감액을 구분한다. 광고는 종료한 러쉬 기회를 복원하지 않는다. 킵한 러쉬는 정산에서 제외하는 후보안이다.

펫 발견·새 기록을 함께 보여주는 구성, 다시보기, 수령/닫기·재표시 방식은 미정이다. 광고 실패·취소·닫기에도 감액 기본분을 보존하고, 복원분은 결산 ID별 한 번만 지급하는 설계를 제안한다. 펫 수집품과 구슬·연짱 기록은 코인 감액 대상에 넣지 않는 안을 우선한다.

### 5.5 최초 시작 — 기본 방·첫 당첨·첫 구매

**합의:** 처음부터 기본 가구가 배치된 여러 콘셉트의 방 중 선택하고, 튜토리얼에서 첫 당첨을 보장해 구슬 지급을 경험한 뒤 첫 소품 구매·배치까지 연결한다. 빈 방을 필수 가구로 채우기보다 마음에 드는 공간에 취향을 더하는 경험을 지향한다. 콘셉트 수·이름과 상품 구성은 미정이다.

| 순서 | 경험 | 상태와 범위 |
|---|---|---|
| 기본 방 선택 | 기본 기계·의자·가구가 갖춰진 콘셉트 중 선택 | 방향 합의. 따뜻한 원룸·작업실·레트로 취미방은 예시 |
| 기계 조작 | 발사와 세기 조절을 간단히 체험 | 안내 방법·소요시간은 제안 |
| 첫 당첨 | 튜토리얼 전용 보장 당첨으로 지급과 변형 러쉬 경험 | 첫 당첨 보장 합의. 진입 시점·러쉬 시연 분량 미정 |
| 첫 구매 | 첫 당첨의 기본 지급분으로 구매 가능한 소품 중 선택 | 연짱 성공 없이 구매 가능하게 구성. 상품·가격 미정 |
| 첫 배치 | 소품을 배치하고 달라진 방을 확인한 뒤 자유 플레이 | 구매·배치 연결 합의. 배치 방식은 제안 |

첫 구매에는 추가 연짱·펫 발견·광고 시청을 요구하지 않는다. **가격 기준은 첫 당첨 기본 지급분으로 얻는 사용 가능 재화 이내**로 둔다. 구슬 지급량을 코인 가격과 직접 같은 숫자로 놓지 않고, 전환 규칙을 정한 뒤 가격을 산출한다. 첫 구매를 위해 반드시 기본 지급분 전액을 쓰게 하는 것은 아니다.

**합의 방향:** 보장 당첨은 일반 추첨과 구분하고 첫 보상은 한 번만 지급한다. 이후 통상은 일반 확률을 사용한다. 개발용 ‘러쉬 체험’ 버튼은 기록을 초기화하는 기능이므로 출시용 튜토리얼과 동일 취급하지 않는다.

**제안:** 구슬은 정해진 속도로 지급하고, 지급 중에도 상품을 살펴볼 수 있게 한다. 구매 가능한 잔액에 도달하면 선택·배치로 이어간다. 긴 연짱 종료나 모든 시연 관람을 구매 조건으로 두지 않는다. 튜토리얼 기록은 일반 개인 기록·그랑프리와 구분한다.

**미정:** 안내 건너뛰기·재시청, 도중 종료·복귀, 보장 러쉬 범위, 구매 취소와 나중에 구매하기, 기종 변경 후 재안내 여부. 재시작이나 재설치로 최초 보상이 중복 지급되지 않도록 완료·지급·구매 상태를 구분해 저장한다.

## 6. 캐릭터와 공간

**합의:** 캐릭터가 자신의 공간에서 파칭코를 하는 모습을 관찰한다. 시작 시 여러 기본 방 콘셉트 중 선택하고, 기본 가구가 갖춰진 공간에 장식을 추가한다.

**제안:** 콘셉트 간 기본 기능·초기 가치를 비슷하게 두고 분위기를 달리한다. 기존 가구와 새 소품이 함께 어울리게 만든다. 콘셉트 변경 비용·기본 가구 교체·회수·판매 규칙은 미정이다.

**제안:** 초기 동작은 대기, 평상시 플레이, 자세 변경, 리치 집중, 당첨 반응으로 제한한다. 상태를 전달하는 동작부터 만들고 복잡한 생활 시뮬레이션은 후순위로 둔다.

초기 장식 후보는 의자, 조명, 벽 장식, 바닥·벽 테마, 작은 테이블이다. 방의 조명과 기계 조명이 충돌해 판면이 보이지 않는 상황을 피한다. 캐릭터의 취향·친밀도·성장 능력치는 아직 도입하지 않는다.

### 6.1 세계관과 기계 캐릭터

**합의:** 가상 기계마다 고유한 캐릭터를 제작하고, 캐릭터와 기계의 정체성을 방 장식·굿즈로 확장한다. 단순히 돈을 잘 버는 기계뿐 아니라 좋아하는 캐릭터와 분위기 때문에 기계를 선택할 수 있게 한다.

**제안:** 여러 가상 파칭코 브랜드가 기계와 마스코트를 선보이고, 그랑프리가 이들을 연결하는 행사인 세계를 구성한다. 플레이어는 자기 방에 기계와 굿즈를 모으는 수집가다. 브랜드 수·이름·관계와 상세 서사는 미정이다.

플레이어의 분신인 **방의 캐릭터**와 판면·연출·상품의 주인공인 **기계 마스코트**는 역할을 구분한다. 게임 전체 안내를 담당하는 공통 마스코트를 별도로 둘지는 제안 단계다.

기계 마스코트는 이름·외형만 정하지 않고 성격과 동작을 기믹에 연결한다. 예를 들어 구슬을 모으는 성격은 저장·방출 장치, 무대를 여는 역할은 변형 러쉬와 연결할 수 있다. ‘별빛 극장 안내원’, ‘도깨비 공방’, ‘심해 우체국’은 대화에서 나온 아이디어 예시이며 확정된 캐릭터나 출시 라인업이 아니다.

### 6.2 굿즈와 수집 보상

**합의:** 기계 캐릭터를 간판·포스터·인형 등 게임 내 굿즈로 활용한다. 실제 상품 제작·판매는 현재 범위에 포함하지 않는다.

| 분류 | 획득 경로 초안 | 역할 |
|---|---|---|
| 기본 굿즈 | 꾸미기 코인 구매 | 좋아하는 캐릭터로 공간 구성 |
| 플레이 기념 굿즈 | 첫 러쉬·누적 플레이·개인 기록 달성 | 기계와 함께한 경험 표시 |
| 그랑프리 굿즈 | 참가 기념·입상 보상 | 대회 기억과 성취 표시 |

위 획득 경로와 달성 조건은 **제안**이다. 기본 캐릭터 수집을 상위권 보상으로만 잠그지 않고, 대회 보상은 특별한 의상·명판·트로피로 차별화하는 방향을 검토한다. 외형 보상이 기계 성능을 높이는지는 기존 경제 원칙과 함께 결정하며, 초기에는 외형 중심을 제안한다.

제작 검토 시 마스코트가 작은 판면 아이콘, 러쉬 중 동작, 방에 놓인 인형에서 같은 캐릭터로 인식되는지 확인한다. 초기에는 첫 기계 마스코트를 우선 검증하고 여러 브랜드와 캐릭터를 한꺼번에 제작하지 않는다.

### 6.3 방의 펫과 랜덤 수집 — 제안
**이번에 채택한 기획 초안:** 방에서 활동하는 펫이 가끔 외출해 수집품을 가져온다. 접속 중과 부재 중 모두 발견 가능하게 검토한다. 기계의 당첨·러쉬와 별도로 방에서 일어나는 사건 및 개인별 수집 차이를 제공한다. 실제 구현·재미 검증은 아직 없다.

첫 시험은 펫 한 마리와 소수의 배치 가능한 소품을 후보로 둔다. 평소 이동·휴식·외출·귀환 표현을 검토하되, 먹이·건강·친밀도·성장·반복 탐험 지시를 요구하는 관리 시스템은 초기 초안에 넣지 않는다. 펫 종류 수집이나 육성까지 승인된 것은 아니다.

기계 마스코트·플레이어 캐릭터·펫의 역할을 구분한다. 기계 포스터·첫 러쉬 기념품 등은 해당 기계 경험과 연결하고, 펫은 별도 생활 소품을 가져오는 안을 제안한다. 구체적인 수집품 테마는 미정이다.

| 항목 | 방향 또는 남은 결정 |
|---|---|
| 발견 시점 | 접속·부재 중 발생 제안. 주기·확률·상한·보관량 미정 |
| 발견 처리 | 즉시 클릭 없이 보존 제안. 재접속으로 새 추첨·중복 획득하지 않도록 설계 |
| 수집품 | 방에 놓는 소수 소품으로 시험. 목록·희귀도·기계 굿즈와의 경계 미정 |
| 중복 | 허용 여부, 교환·분해·재추첨 등 모두 미정 |
| 불운 보호 | 장기간 미발견·중복만 발생할 때의 처리 미정. 펫이 반드시 불운을 해소한다고 가정하지 않음 |
| 광고 관계 | 펫 발견·외출에 광고를 필수 조건으로 두지 않는 초기안. 희귀품 배수 미채택 |

동일 조건의 시행 횟수가 커지면 관측 당첨 비율이 이론값에 가까워지는 경향이 있으나, 개별 러쉬·유한한 경기 결과가 같아지는 것은 아니다. 펫 도입 목적은 확률 경쟁을 대체하는 것이 아니라 개인별 수집과 관찰 경험을 넓히는 것이다.

## 7. 파칭코 공통 규칙

### 7.1 발사와 입상

- 핸들 양옆 화살표로 힘을 조절한다. 손을 떼면 설정을 유지한다.
- 구슬끼리, 구슬과 핀·벽의 충돌을 표현한다.
- 발사 레일과 상단의 둥근 경로를 통해 세기에 따른 좌·우 이동을 제공한다.
- 구슬이 시동구 유효 영역을 실제로 통과할 때 보류를 추가한다.
- 보류 상한 초과 입상은 추가 추첨을 저장하지 않는다. 상구 처리 규칙은 공통 사양으로 명시한다.
- 보류가 있는 상태에서 가능한 다음 회전을 순차 처리한다.

### 7.2 일반 추첨과 리치

현재 가상 기기는 회전 시작 시 당첨 여부를 정하고 숫자와 룰렛으로 결과를 표현한다. 숫자 일치는 당첨 결과와 일관되어야 한다. 물리 구슬의 입상과 숫자 추첨을 혼동하지 않는다.

### 7.3 헤소 가독성 — 알려진 개선 과제

현재 Mk.III는 두 개의 시동구와 넓은 유도 가이드를 사용한다. 사용자는 시선 분산 및 가이드에 들어온 구슬이 최종 입구에서 빠지는 상황을 지적했다.

**후속 설계 방향:** 중앙에 관심을 모으고, 입상률 조절을 최종 구멍보다 앞쪽의 분기 구간에서 수행한다. 최종 가이드를 제대로 탄 구슬은 대부분 입상하게 한다. 모든 구슬을 입상시키거나 숨은 확률로 걸러내는 방식은 사용하지 않는다. 시동구 수와 최종 판면 변경은 다음 기계 설계에서 결정한다.

## 8. 변형 러쉬

**합의된 흐름:** 최초 당첨 → 지급 → 기계 변형 → 러쉬 → 연짱 중 변형 유지 → 실패 시 원래 기계로 복귀.

현재 Mk.III에서는 중앙 숫자 룰렛이 접히고 양쪽 프레임이 벌어져 내부 회전 접시를 드러낸다. 세 구슬 중 하나라도 연장 영역에 도착하면 추가 당첨 한 번으로 처리한다. 한 도전에서 여러 구슬이 성공해도 여러 번 지급하지 않는다.

| 상태 | 진입 | 행동 | 종료 조건 |
|---|---|---|---|
| 일반 | 초기·러쉬 종료 | 시동 입상과 숫자 추첨 | 당첨 |
| 당첨 해제 연출 | 최초 당첨 | 짧은 간격과 잠금 해제음 | 지급 시작 |
| 최초 지급 | 첫 당첨 | 정해진 지급량 처리 | 지급 완료 |
| 변형 | 최초 지급 완료 | 장치를 열고 내부 구조 노출 | 개방 완료 |
| 러쉬 도전 | 변형 완료·연짱 지급 완료 | 세 구슬 결과 표시 | 성공 또는 전부 실패 |
| 연짱 지급 | 러쉬 성공 | 열린 상태에서 추가 지급 | 다음 도전 |
| 복귀 | 러쉬 실패 | 장치 닫기 | 일반 상태 |

현재 내부 러쉬 구슬은 최종 각도 추첨을 경로·감속으로 표현하는 간이 모델이다. 외부 판면의 자유 구슬 물리와 동일한 모델이 아니다. 후속 기계에서 실제 물리 기반 장치를 쓸지, 결과를 연출하는 장치를 쓸지 기계별로 명시한다.

### 8.1 러쉬 킵 — 기능 후보
러쉬 중 전용 버튼에서 광고를 보고 현재 러쉬 한 개를 보관한 뒤, 나중에 이어보는 안을 유지한다. 앱을 떠나야 하는 순간의 광고 부담 때문에 종료 시 강제 안내보다 러쉬 중 미리 선택하는 방향이다. 구현 확정이나 초기 출시 필수 기능은 아니다.

- 킵한 러쉬는 부재 정산에서 제외하고, 부재 가동은 통상에서 시작하는 초안이다.
- 부재 중 새 당첨·러쉬는 자동 처리하며 추가로 킵하지 않는 안을 검토한다.
- 복귀는 통상으로 하므로 원할 때 킵을 꺼내 이어본다. 이어보는 동안에는 해당 러쉬만 진행하는 안이다.
- 기계·사양 버전, 연짱, 이미 지급한 금액, 미지급 확정분과 보관 ID를 보존해 재추첨·중복 지급을 막는 설계를 제안한다.
- 보관 기간·교체·기계 변경·취소·광고 실패·킵 복귀 도중 재종료 및 시간 회계는 미정이다. 킵으로 수익·가동 시간을 늘릴 수 없는지 검증한다.
- 이번 논의는 일상 모드만 대상으로 한다. 그랑프리는 별도로 정리한다.

## 9. 지급 라운드와 음향

### 9.1 방향

**합의:** 구슬 지급의 소리와 움직임을 핵심 쾌감으로 삼는다. 현재보다 천천히, 라운드별로 끊어서 지급되는 느낌을 지향한다.

**제안:** 공통 지급 시스템을 만들고 기계별로 총 지급량, 라운드 수, 라운드당 지급량, 지급 속도와 휴지 시간을 설정한다. 모든 기계의 수치를 같게 고정하는 것은 확정되지 않았다.

예시 초안은 총 300개를 60개씩 5라운드로 나누고, 각 라운드 2초 지급 후 0.5초 쉬는 방식이다. 이는 미구현·미승인 예시이며 실기 라운드 규격을 뜻하지 않는다.

러쉬 도전 횟수, 연짱 수, 한 당첨의 지급 라운드는 서로 다른 용어로 사용한다. 지급 라운드가 다섯 번이라고 5연짱으로 기록하지 않는다.

### 9.2 지급의 정확성

- 실제 보상은 지급 이벤트로 집계하고 애니메이션 입자 수와 분리한다.
- 라운드 ID와 지급 순서를 기록해 복귀·재접속 시 중복 지급을 막는다.
- 지급 도중 앱을 닫았을 때 남은 지급·다음 러쉬를 어떻게 이어갈지 공통 상태 규칙을 적용한다.
- **합의:** 지급 라운드·휴지·러쉬 소요시간도 실제 가동 시간에 포함한다. 부재 계산이 빠르게 실행된다는 이유로 가동 시간을 생략하지 않는다. 재접속이 지급·러쉬 시간 건너뛰기로 수익을 늘리는 수단이 되면 안 된다.
- 확정된 미지급 구슬을 보존하면서 통상으로 복귀할 때 남은 지급 시간을 처리하는 상세 회계는 D23에서 결정한다. 아직 구현 해법이 검증된 것은 아니다.

### 9.3 음향 구성

평상시 발사음·핀 충돌음, 리치의 기계식 걸림음, 당첨 잠금 해제음, 지속적인 구슬 흐름, 불규칙한 금속 충돌음, 받침 울림, 변형 모터음, 마지막 몇 알의 잔향을 구분한다.

현재는 합성음이다. 후속 품질 개선 시 직접 녹음 또는 사용 권한이 있는 구슬·받침 녹음을 검토한다. 소리와 보이는 충돌을 가능한 범위에서 연결하고, 음소거·앱 중단 시 지속음이 남지 않게 한다. 마스터 음량과 기계음·음악 분리는 설정 화면 후보로 둔다.

## 10. 재화와 경제

**합의 방향:** 기록용 구슬과 꾸미기 진행 재화를 분리하고 획득 보상을 공간·기계 수집에 사용한다.

| 항목 | 역할 | 미결정 사항 |
|---|---|---|
| 구슬·기계 기록 | 발사, 지급, 차옥, 당첨과 연짱의 원자료 | 일상 무제한 가동 합의. 그랑프리의 제한 자원·고갈은 미정 |
| 꾸미기 코인(가칭) | 가구·외형·기계 해금에 소비 | 당첨 기반 획득을 우선 시험. 전환량·가격·기본 지급 필요성 미정 |
| 경쟁 점수 | 기록에서 산출한 비교 지표. 소비 재화가 아님 | 누적 지급·차옥·별도 점수 중 선택 |

현재 시제품은 발사 비용을 잔고에서 차감하지 않고 누적 지급량만 표시한다. 따라서 현재 ‘획득 구슬’을 순이익으로 해석하면 안 된다. 실기 손익이나 천 엔당 회전율과 직접 비교하지 않는다.

**합의:** 일상은 구슬 충전 없이 무제한 가동한다. 보유 잔고 부족을 이유로 일상 가동을 중단하지 않는다. 무제한 가동은 무제한 오프라인 시간 인정을 뜻하지 않는다.

**제안·검증 가설:** 코인은 당첨 기반으로 획득하고 펫이 미당첨 구간의 수집 재미를 보완한다. 펫 발견은 코인 최소 수입 보장이 아니다. 불운한 세션의 구매 지연과 수집 만족을 확인해 기본 코인 지급 필요성을 재검토한다. 꾸미기 구매로 과거 경쟁 기록을 감소시키지 않고 광고로 복원한 코인은 기계 지급 원자료와 분리한다. 전환 시점·대상 지급량·소수점 처리는 미정이다.

기계 구입을 단순한 상위 수익 장비 구매로 만들지 않는 방향을 우선 검토한다. 외형 장식이 경쟁 성능을 바꾸지 않도록 하는 것도 제안이며 최종 경제 사양은 별도 확정한다.

첫 구매 가격은 5.5의 보장 당첨 기본 지급분을 기준으로 설계한다. 일반 소품 전체를 이 가격에 맞추는 것은 아니다. 첫날·다음 날 구매량과 큰 가구의 가격은 미정이다.

### 10.1 부재 코인 감액과 광고 복원 — 합의
같은 시간 대비 부재 중 코인 수익을 낮추고, 광고 시청 시 해당 부재 정산에 온라인과 같은 코인 전환율을 적용한다. 광고 미시청의 손실감을 시청 동기로 삼는 방향이다. 감액률과 광고 한 번이 적용되는 정산 범위는 미정이다.

개념상 감액 전 기준 코인을 C, 부재 지급 비율을 r(0 < r < 1)로 두면 기본분은 r×C, 광고 복원분은 (1−r)×C, 총수령은 C다. 소수점 처리는 별도 결정한다. r=0.5일 때만 기본분 대비 2배이며, 50%를 확정한 것은 아니다.

C는 인정 시간 내 부재 결과와 확정 지급 보존 규칙을 적용해 계산한다. 광고로 미래 연짱·24시간 초과 가동·구슬 기록을 추가하지 않는다. 미완료 러쉬의 연장 기회를 종료하므로 광고 시청 후에도 같은 시간 온라인 플레이와 총수익이 일치한다는 뜻은 아니다. 온라인 우위는 개별 세션의 보장 수익이 아닌 기대 수익 방향이다.

## 11. 방치·오프라인 진행

### 11.1 현재와 합의된 방향
**현황:** 숨긴 브라우저 탭에서는 진행이 멈춘다. 서버·계정 저장·오프라인 정산은 미구현이다.

**합의:** 일상 부재 진행은 최대 24시간 인정하고, 복귀 시 기계는 항상 통상 상태로 시작한다. 짧은 상한으로 반복 접속을 요구하는 피로를 줄이려는 결정이다. 구슬 무제한 가동과 부재 인정 상한은 별개다. 인정 구간의 기준 시점·재접속 분할·멀티기기 처리는 상세 설계가 필요하다.

### 11.2 정산 경계와 러쉬
정산 경계는 복귀 시점과 24시간 상한 중 먼저 도달한 시점이다.

| 경계 상태 | 합의된 처리 |
|---|---|
| 통상 | 인정 구간의 결과를 마감하고 통상으로 복귀 |
| 러쉬 진행 중 | 남은 미확정 연장 기회를 종료. 미래 연짱을 끝까지 미리 계산해 지급하지 않음 |
| 당첨 확정·지급 중 | 이미 지급한 구슬과 확정된 미지급 구슬은 보존. 코인 전환은 10.1의 감액·복원 규칙 적용 |
| 킵한 러쉬 | 별도 보관·정산 제외 후보. 8.1 참조 |

24시간 상한도 같은 마감 원칙을 적용한다. 마지막 러쉬를 상한 밖까지 추가 추첨해 끝내는 안은 채택하지 않는다. 미확정 기회의 종료는 실제 추첨 낙첨과 구분해 기록하는 안을 제안한다. 종료의 손실 폭이 작은지는 아직 검증되지 않았다.

**미정:** 통상 보류·진행 중 숫자 회전의 미확정분 처리와 확정 시점 정의. 이미 당첨이 확정된 결과는 보호하되, 미래 기회 전체를 소급 확정하지 않는다.

### 11.3 시간·보상의 일관성
- 의도한 온라인 기대 수익 우위와 부재 감액은 허용한다. v0.4의 앱 표시 여부에 따른 기대 성능 동일성 요구는 이 합의로 대체한다.
- 발사·추첨·러쉬·지급·휴지 시간을 유효 가동 시간에 반영한다. 재접속·킵으로 시간 비용을 생략해 수익을 늘리지 않는다.
- 확정 미지급분을 보존하는 순간 즉시 전액 처리할지, 별도 지급 채무로 처리할지 등 시간 회계는 D23의 미정 사항이다. 사용자에게 대기·시간 차감을 강제하는 안을 임의 확정하지 않는다.
- 저성능 프레임 손실, 시계 조작, 재설치·멀티기기·정산 반복으로 결과를 유리하게 바꾸거나 중복 지급하지 않도록 한다.
- 광고와 다시보기는 확정된 구슬·당첨·연짱 결과를 재추첨하지 않는다. 코인 광고 복원은 별도 지급 기록으로 관리한다.

### 11.4 계산 모델 — 미정
동일 물리와 검증된 경량 모델 중 선택하지 않았다. 입상·당첨·연짱 사건과 소요시간을 어떻게 계산할지 검증한다. 의도한 감액·경계 종료의 영향과 계산 오류로 인한 차이를 분리해 측정한다. 단순 평균 수익만 적용하면 사건·분산이 사라진다는 기존 검토를 유지한다. 이번 규칙은 그랑프리에 자동 적용하지 않는다.

## 12. 경쟁과 랭킹

**합의:** 일상적인 수집·꾸미기 플레이와 기간 한정 이벤트인 **가상의 파칭코 그랑프리**를 구분하는 방향으로 진행한다. 과금 우위 없는 경쟁과 배속 제외 원칙을 유지한다. 대회명은 가칭이다.

### 12.1 일상과 대회의 관계

| 항목 | 일상 플레이 초안 | 그랑프리 초안 |
|---|---|---|
| 목적 | 기계 감상·수집·꾸미기·개인 기록 | 기간 내 기록 경쟁 |
| 기계 | 선택한 보유 기계 | 지정 기계 |
| 진행 | 최대 24시간 인정·통상 복귀 합의, 계산 모델 미정 | 동일 경기 분량과 참가 조건 검토 |
| 보상 | 꾸미기 재화·기계 기념품 | 참가 기념품·트로피·기념 외장 |
| 유지 | 보유품과 개인 진행 유지 | 대회 종료 후 기록 마감, 보상은 보유 |

일상 진행의 24시간 상한·통상 복귀는 합의다. 그 외 표의 세부 규칙은 **제안**이다. 이번 보완에서는 그랑프리 규칙을 추가 확정하지 않는다. 대회 때문에 일상 플레이가 막히지 않도록 하며, 방의 기계가 대회 모드로 바뀌는 표현과 별도 경기장 표현 중 선택한다. 두 모드의 동시 가동·시간 중복 인정 여부는 미정이다.

### 12.2 첫 그랑프리 운영안 — 제안

지정 기계 한 대, 동일 발사 수, 동일 참가 횟수로 시작한다. 미보유 이용자에게도 대회용 기계를 제공해 수집 진척으로 참가가 막히지 않게 하는 방안을 검토한다. 마지막 유효 구슬이 시작한 추첨·러쉬는 종료까지 처리하고, 이후 새 일반 플레이를 점수에 추가하지 않는 종료 규칙을 제안한다.

대안은 동일 시간 경기다. 이 경우 지급·러쉬 소요시간도 기계 성능에 포함되므로 발사 수 기준과 섞어 비교하지 않는다. 경기 분량·참가 횟수·개최 주기·점수 산식·재접속·부재 중 경기 진행은 미정이다. 상시 누적 랭킹을 별도로 추가할지도 확정하지 않았다.

**개인 기록 제안:** 최고 연짱, 단일 러쉬 최고 지급, 최초 달성일, 누적 당첨. 대회에 참여하지 않아도 개인 목표를 제공한다. 현재 시제품에는 그랑프리와 랭킹이 구현되지 않았다.

### 공통 기록 원칙 — 제안

기계 ID와 사양 버전, 경쟁 기간, 유효 가동 시간, 발사 수, 시동 입상 수, 일반 회전 수, 최초 당첨 수, 러쉬 추가 당첨 수, 실제 지급량, 체험 여부를 보존한다. 총 대당첨 표시와 최초 당첨·추가 당첨 원자료는 분리한다.

서로 다른 기계를 같은 기대값이라는 이유만으로 단순 합산하지 않는다. 변동성·지급 소요시간·상한 차이까지 평가해야 한다. 초기에는 같은 기계·같은 사양 버전의 비교가 우선이다. 밸런스 변경은 시즌 경계 적용 또는 기록 분리 정책이 필요하다.

실시간 갱신 주기는 서버 비용과 표시 반응을 확인해 정한다. 판면의 모든 프레임을 순위 서버에 보내는 구조를 전제로 하지 않는다. 서버 검증·확정 기록과 로컬 체험 데이터를 분리한다.

### 12.3 제한 구슬과 광고 충전 — 제안
그랑프리에 제한 구슬을 두고 광고로 충전하는 안을 후보로 기록한다. 광고 시청이 점수에 반영되는 추가 발사·참가 기회를 주면 경쟁 우위가 생길 수 있다. 동일 경기 조건안과 충돌할 수 있으므로 아직 채택하지 않는다.

점수에 반영되는 충전과 연습용 구슬·비경쟁 보상을 구분한다. 전자를 검토한다면 참가·충전 상한, 미시청 이용자의 조건, 점수 집계 및 종료 규칙을 함께 결정한다. 광고를 보면 더 유리한 구조를 과금 우위 없는 경쟁과 동일하다고 표현하지 않는다. D04·D05·D15에서 먼저 경기 조건을 정한 뒤 판단한다.

## 13. 기계 수집과 콘텐츠 제작

**합의:** 새 가상 기계를 계속 추가해 흥미를 유지한다. 실제 파칭코의 큰 틀을 공유하되 기계마다 다른 경험을 만든다.

공통 엔진은 발사·입상·보류·추첨·지급·저장·기록을 담당한다. 기계별 데이터와 연출은 판면, 확률, 상태별 시간, 리치, 변형, 러쉬 장치, 음향을 담당한다. 콘텐츠와 공통 규칙의 경계를 먼저 검증한다.

### 13.1 실제 인기 기종에서 출발하는 재해석

**합의:** 초기 가상 기계는 실제 인기 기종의 기믹·콘셉트를 모티브로 삼아 우리만의 테마와 캐릭터로 비틀어 개발한다. 익숙한 재미의 구조를 출발점으로 삼되, 인기 기종을 참고했다는 이유만으로 우리 게임에서도 흥행·재미가 보장된다고 판단하지 않는다.

**제안하는 제작 순서:**

1. 참고 기종을 선정하고 공식 설명·실제 플레이 관찰 등 출처를 기록한다.
2. 재미의 원인을 분해한다. 예: 작은 신호의 강한 의미, 리치의 지연과 해소, 저장된 구슬의 방출, 연장 여부가 읽히는 장치, 지급음의 리듬.
3. 가져올 경험과 새롭게 만들 요소를 구분한다. 확률·판정·연출에 대해 확인된 사실과 추정도 나눈다.
4. 새로운 캐릭터의 성격·테마를 장치 동작과 연결하고, 이름·그래픽·음향·연출 구성을 설계한다. 기존 자산은 자체 제작 또는 권리 확보 원칙을 따른다.
5. 판면·변형 러쉬·대표 굿즈 한 가지를 함께 검토한다. 기계가 재미있는지와 캐릭터를 모으고 싶은지를 각각 확인한다.
6. 실제 플레이로 입상 납득도, 긴장과 해소, 소리, 장기 반복성을 확인하고 제작 비용을 기록한다.

참고 기종명과 구체적인 모티브 대응표는 아직 정하지 않았다. 특정 인기 기종의 캐릭터·로고·영상을 그대로 사용하는 것은 이번 방향에 포함하지 않는다.

## 15. 초기 과금과 출시 조건

초기 직접 결제 없이 개발하는 방향을 유지한다. 부재 코인 감액·광고 시청 시 감액분 복원을 수익모델 방향으로 합의했다. 초기 버전 도입 여부는 미정이다. 향후 직접 결제는 사용자 피드백과 운영 비용을 바탕으로 별도 결정한다. 과거 논의한 ‘답답함 해소 과금’은 채택된 사양이 아니다.

**제안:** 과금 검토 시 먼저 방 테마·캐릭터 의상·기계 외장 등 외형 상품을 검토한다. 확률·속도·가동 시간·성능을 판매할 경우 기존 경쟁 원칙과 충돌하므로 같은 시스템에 무심코 추가하지 않는다.

파칭코와 모의 도박 요소를 유지한다는 방향은 확인되었다. 이것이 출시 등급이나 유통 승인을 확보했다는 뜻은 아니다. 환전·현금성 경품·유저 간 현금 거래는 현재 범위에 없다.

2026-09-08 확인한 Apple 공식 안내는 빈번한 모의 도박을 현행 글로벌 18+ 및 한국 지역 19+ 항목에 포함하고, 한국 배포에 해당 콘텐츠의 등급분류번호(RCN)를 요구한다. 실제 적용은 플랫폼·지역·최종 콘텐츠별 확인이 필요하다. Android를 Apple 기준으로 자동 판정하지 않는다. 출시 국가, 배포 플랫폼, 필요한 등급 절차는 출시 준비 전에 확인한다.

참고: [Apple 연령등급 정의](https://developer.apple.com/help/app-store-connect/reference/app-information/age-ratings-values-and-definitions/), [Google Play 실제 금전 도박 정책](https://support.google.com/googleplay/android-developer/answer/9877032?hl=en). 후자는 현금·현실 가치 보상 경계를 검토하기 위한 자료이며 현재 게임의 등급 확정 근거는 아니다.

### 15.1 부재 감액분 복원 광고
**합의:** 부재 정산 코인을 감액 지급하고 광고 시청 시 감액분을 복원한다. 광고를 보지 않으면 덜 받는다는 동기를 의도한다. 온라인 코인을 두 배로 올리거나 접속 여부와 무관한 별도 보너스로 대체하지 않는다.

전액의 기준은 10.1의 C이며 온라인과 같은 전환율을 뜻한다. 미래 러쉬 기회와 총수익의 동등성은 보장하지 않는다. 감액률·광고 한 번의 적용 범위·횟수·재시도·갱신·초기 도입 시점은 D21에서 결정한다.

**설계 제안:** 광고 취소·실패·미제공·앱 종료에도 기본 감액분을 보존하고, 동일 결산의 복원분을 중복 지급하지 않는다. 구슬·당첨·연짱 기록 및 펫 수집품은 코인 감액 대상에 넣지 않는다. 광고 후 추가로 발생한 새 가동 보상에 과거 광고를 재사용할 수 있는지 등 적용 경계는 미정이다.

광고 시청 시 세션이 1분보다 길어질 수 있다. 미시청의 낮은 수입은 의도된 차이이며, 광고 이용률과 함께 이탈·수집 지연·시청 피로를 측정한다. 광고 SDK·사업자·정책 적합성은 이번에 확인하거나 선정하지 않았다. 러쉬 킵 광고는 별도 기능 후보이며, 그랑프리는 후속 논의로 둔다.

## 16. 초기 개발 범위 — 제안

### 단계 1: 방치형 경험 연결

사용 중인 방 한 개, 캐릭터 한 명, Mk.III 한 대, 소수의 장식, 방↔기계 전환, 로컬 진행 저장, 기본 꾸미기 구매를 연결한다. 제품 방향은 여러 기본 방 콘셉트 선택이며, 첫 검증은 공통 방 구조에 가구·색상 배치를 달리하는 소수 프리셋을 제안한다. 정확한 제작 수는 미정이다. 첫 당첨 보장부터 소품 선택·구매·배치까지의 튜토리얼을 연결한다. 지급 라운드 개선을 함께 검토한다. 온라인 랭킹과 대규모 콘텐츠를 앞서 만들지 않는다.

**확인할 결과:** 기계를 확대하지 않은 방 화면도 관찰할 이유가 있는지, 당첨이 없어도 진행을 느끼는지, 새 장식을 배치했을 때 장면이 달라지는지.

**추가 구현 후보:** 펫 한 마리와 소수 수집품으로 관찰·발견·배치를 시험한다. 초기 단계에 포함할지와 작업량은 별도 결정하며 다종 펫·육성은 범위에 넣지 않는다.

### 단계 2: 부재와 복귀

합의된 24시간·통상 복귀·감액/광고 복원 규칙에 따라 시간·보상·중단 상태를 연결한다. 확정 미지급분의 시간 회계는 구현 전에 결정한다. 복귀 팝업과 개인 기록을 제공한다. 펫 발견·기본 코인 필요성을 함께 시험할 수 있다. 광고는 보상 구분과 복귀 보존을 먼저 설계하고 실제 연동 시점은 별도 결정한다. 다시보기는 핵심 결산 이후로 둔다.

**확인할 결과:** 여러 번 재접속해도 중복 지급되지 않는지, 지급·러쉬 중 종료가 일관되게 이어지는지, 켜둔 상태와의 성능 차이가 허용 범위인지.

### 단계 3: 기계 확장과 경쟁

두 번째 기계로 모티브 재해석·캐릭터·굿즈와 데이터·연출 교체 구조를 검증한다. 그랑프리의 경기 조건과 점수 산식을 결정하고, 기록 확정 구조를 연결한 뒤 외부 경쟁 시험을 진행한다.

초기 제외 항목은 다수 기계 동시 수익, 길드·거래, 복잡한 캐릭터 성장, 대형 영상 콘텐츠, 유료 확률·배속, 현금성 보상이다. 일정·예산·팀 규모는 미정이다.

## 17. 검증 계획

| 질문 | 확인 방법 |
|---|---|
| 입상이 납득되는가? | 가이드 진입 후 결과 관찰, 실제 기기에서 구슬 경로 확인 |
| 방만 보아도 상태가 전달되는가? | 확대 없이 리치·당첨·러쉬를 구분하는지 관찰 |
| 지급이 즐거운가? | 휴대폰 스피커·이어폰에서 소리와 입자 타이밍 비교 |
| 당첨 없는 시간도 견딜 만한가? | 불운한 세션을 포함한 플레이 관찰, 꾸미기 진행 확인 |
| 다시 접속할 이유가 있는가? | 결산 이해, 다음 구매 목표, 자발적 재방문 관찰 |
| 기계를 바꿀 이유가 있는가? | 수익 수치 외에 선호하는 소리·연출·형태가 생기는지 확인 |
| 기록이 공정한가? | 재접속·프레임 차이·시계 변경·버전 차이·중복 처리 시험 |

측정 후보는 방/기계 화면 체류 비율, 최초 구매까지 시간, 시동 입상률, 분당 유효 회전, 보류 포화·공백 시간, 당첨 간격 분포, 러쉬 길이 분포, 실제 지급량, 재방문과 기계 교체 빈도다. 목표 수치는 아직 정하지 않는다. 평균만 확인하지 않고 긴 미당첨 구간과 극단적인 연짱도 확인한다.

### 17.1 플레이 패턴 조사와 검증 가설

[탐색 조사 v0.1](PLAY-PATTERNS-RESEARCH-v0.1.md)의 학술 자료와 공개 후기는 짧은 확인, 다른 활동과 병행, 가끔 하는 깊은 선택, 익숙한 반복, 수집 목표, 휴식 후 복귀를 설계 가설로 검토하는 근거다. 선별된 자료이며 한국 모바일 파칭코 이용자의 대표 표본이 아니다. 자료별 열람 범위와 출처는 조사 문서를 따른다.

| 가설 | Project H에서 시험할 내용 | 확인할 결과 |
|---|---|---|
| H1 | 짧은 확인과 긴 관찰을 모두 지원 | 짧게 나가도 만족하는지, 자발적으로 확대하는지 |
| H2 | 관람·즉시 조작 여부와 확정 보상 분리 | 놓친 장면에 대한 아쉬움과 손실 불안을 구분 |
| H3 | 복귀 결산에 당첨·연짱 사건 기록 제공 | 단순 재화 결산 대비 기억·이해·제작 비용 비교 |
| H4 | 굿즈가 방에서 눈에 보이는 진행 제공 | 구매·배치 후 변화 인식, 개인 수집 목표 |
| H5 | 그랑프리를 선택적인 집중 구간으로 구성 | 참가 동기와 미참가 부담을 함께 확인 |
| H6 | 공통 조작은 유지하고 기계 경험을 확장 | 새 기계 학습 부담, 익숙한 기계의 선택 이유 |

위 항목은 **제안·검증 가설**이다. 연구로 오프라인 상한, 하루 접속 횟수, 경기 분량, 랭킹 산식 또는 장기 유지율이 확정된 것은 아니다. 화면을 켜둔 시간을 실제 집중 시간으로 해석하지 않는다. 체류 시간과 함께 접속 목적·종료 만족도·의무감·복귀 이해도를 확인한다.

### 17.2 이번 초안의 추가 검증
- 당첨·펫 발견이 모두 없는 세션, 중복 소품만 얻는 세션에서도 종료 만족을 확인한다.
- 당첨 기반 코인으로 첫 구매·다음 구매가 과도하게 지연되는지 확인한다. 기본 코인 도입 여부는 결과로 판단한다.
- 펫이 기계 관찰을 방해하는지, 방의 분위기와 다음 접속 기대를 높이는지 구분한다.
- 광고 미시청 시 의도된 코인 감액이 정확히 적용되는지, 광고 시 복원 총액이 C를 넘지 않는지 확인한다. 실패·중단·재접속의 중복/손실과 시청 피로·수집 지연을 시험한다.
- 24시간 직전·정각·초과와 복귀 경계의 통상/러쉬/확정 지급을 비교한다. 확정분 보존, 미확정 기회 종료, 통상 복귀를 확인한다.
- 반복 재접속·지급 중 종료·킵 재사용으로 가동 시간 대비 수익이 증가하지 않는지 확인한다. 특히 확정 미지급분 보존의 시간 우회 가능성을 검증한다.
- 러쉬·지급·펫 발견 중 종료를 각각 다루고, 미확정 결과를 재접속으로 유리하게 바꿀 수 없게 한다.
위 항목은 새 검증 계획이며 실행 완료를 뜻하지 않는다.

### 17.3 최초 시작 검증 — 계획

- 추가 연짱·광고·펫 발견 없이 첫 기본 당첨분으로 후보 소품을 구입할 수 있는지 확인한다.
- 지급 중 상품 선택·구매·배치에서 잔액과 실제 지급이 일치하는지 확인한다.
- 당첨·지급·구매·배치 각 단계에서 종료·복귀해 중복 보상·중복 차감·진행 막힘이 없는지 확인한다.
- 첫 당첨이 이후 통상 확률이나 일반 기록에 섞이지 않는지 확인한다.
- 기본 방만으로 공간이 완성돼 보이는지, 첫 소품 배치가 눈에 띄는 개인화인지 관찰한다.
- 안내가 길어지는 구간과 건너뛰기 필요성을 확인한다. 최초 시작 시간을 일반 복귀의 1분 시나리오와 동일하게 강제하지 않는다.

위 검증은 아직 실행하지 않았다. 현재 Mk.III에는 방 선택·최초 구매 튜토리얼이 구현되지 않았다.

### 20.1 다른 PC와 문서를 함께 다듬는 방법

v0.3까지의 인계는 문서 전달 방식이었다. 현재 GitHub 저장소에서 파일을 관리하지만 GPT 대화나 다른 PC의 미커밋 파일은 자동 동기화되지 않는다. v0.5까지의 문서를 보존하고 최초 시작 관련 후속 합의는 `PROJECT-H-GDD-v0.6.md` 초안에 기록한다. 다른 PC에서 작업하기 전 최신 문서와 미전달 수정본을 대조한다. 공통 기준 버전·수정 절·변경 전후·이유·상태·관련 D번호를 함께 기록한다.

동일 기준본에서 나온 서로 다른 수정본을 날짜만 보고 덮어쓰지 않는다. 같은 절의 충돌을 비교하고 사용자가 선택한 내용을 반영해 다음 공통 버전을 만든다. 합의되지 않은 안은 제안으로 유지하며 변경 이력을 남긴다. Windows로 기획 문서만 옮긴 경우 시제품·로컬 링크에 접근할 수 없다는 점을 명시한다.

### 20.4 v0.5 → v0.6 변경 범위

사용자의 ‘튜토리얼에서 첫 당첨을 보여주고 바로 구매로 연결’, ‘몇 가지 콘셉트의 기본 방을 제공하고 추가로 꾸미기’ 제안과 후속 GDD 반영 요청을 근거로 작성했다. 5.5·6장에 경험을, 10장에 가격 기준을, 14·16·17장에 저장·개발·검증 요구를 추가했다. 구체적 방 이름·콘셉트 수·가격·튜토리얼 길이는 확정하지 않았다.

이번 변경은 최초 시작과 꾸미기 범위다. 직전 논의한 독립 지급 대기열의 상세 규칙은 이번 버전에서 정식 개정하지 않았으며 9·11장의 v0.5 시간 회계와 대조해 후속 정리가 필요하다. 에너지 생산 세계관·재화 통합은 별도 탐색 후보이며 채택하지 않았다. 현재 기계 확률과 지급량은 유지한다. 문서 개정은 기능 구현을 의미하지 않는다.
